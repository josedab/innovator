# ADR-0016: LLM-as-Judge for Idea Quality and Adversarial Evaluation

## Status

Accepted

## Context

Innovation ideas generated by LLMs need quality assessment. The project needed a strategy for evaluating, scoring, and stress-testing ideas beyond simple heuristics (word count, keyword matching). Three approaches were considered:

1. **Numeric heuristics** — Score ideas based on length, keyword diversity, readability metrics. Fast and deterministic but shallow; cannot assess feasibility, market fit, or logical coherence.
2. **Human evaluation** — Gold standard for quality but doesn't scale and introduces latency.
3. **LLM-as-judge** — Use the same (or a different) LLM to evaluate, critique, and stress-test ideas through structured prompts and Zod-validated responses.

## Decision

We use **LLM-as-judge** as the primary quality evaluation mechanism across multiple modules:

- **Gauntlet** (`gauntlet/`) — Five specialized adversary personas (Competitor, Regulator, Skeptic, Economist, Engineer) each attack an idea from their domain. Attacks are structured as `{ category, severity, reasoning, evidence, suggestedCounter }` and validated via `AttackSchema`.
- **Red Team** (`redteam/`) — A devil's advocate agent finds fatal flaws, hidden assumptions, and edge cases across multiple attack-defense rounds.
- **Tournament** (`tournament/`) — Ideas compete head-to-head with judge panels scoring on multiple criteria.
- **Debate** (`debate/`) — Multi-perspective structured debate where AI agents argue for and against ideas.

All modules share the same pattern: structured prompts → JSON response → Zod schema validation → typed result. The `wrapUserInput()` and `sanitizeLlmOutput()` utilities from `prompts/sanitize.ts` protect against prompt injection in the evaluation context.

## Consequences

**Positive:**

- **Semantic depth** — LLM judges can assess feasibility, market dynamics, technical complexity, and ethical implications that no heuristic can capture.
- **Structured output** — Zod validation ensures judge responses are machine-parseable, enabling aggregation (e.g., Survivability Index) and comparison.
- **Composable** — Different evaluation modules can be chained: generate → gauntlet → tournament → final ranking.
- **Domain-adaptive** — Adversary personas can be customized for industry-specific evaluation criteria.

**Negative:**

- **Cost multiplier** — Each evaluation round requires LLM calls. A gauntlet with 5 adversaries + strengthen = 6 additional LLM calls per idea.
- **Non-deterministic** — LLM judges may give different scores on the same idea across runs.
- **Circular reasoning risk** — Using the same model to generate and evaluate ideas may not catch systemic blind spots.
- **Gaming susceptibility** — Ideas phrased to please the evaluator model may score artificially high.
